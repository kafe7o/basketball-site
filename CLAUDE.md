# Проект: Баскетболният робот (kafe7o/basketball-site)

Брат на футболния робот (`../football`, kafe7o/football-site) - същата идея и същите правила за честност: прогнозира мачове в НБА и
Евролигата, **записва преди мача** и **мери честно срещу пазара**. Целта не е „сигнали“, а отговор с число: роботът по-добър ли е от пазара?
Почти сигурно не - затова главното е **цената**: във футбола единственото на плюс във всеки период назад е залогът, когато някой букмейкър
плаща поне 3% над честната цена на Pinnacle (`../football/research/price_edge_backtest.py`).

Решения на собственика (2026-10-14): име на хранилището `basketball-site`; първенствата - по преценка, ако спазват всички правила (влизат
само първенства с цени в odds API И история за проверка назад - НБА и Евролига); ключът за odds API е ОБЩИЯТ с футбола.

## Структура

```
run.py               cloud | local | backfill | site | status
hoops/
  config.py          пътища, ключове от .env, таван на кредитите (ODDS_BUDGET_MONTH 3000, резерв 2500 за футбола)
  leagues.py         регистърът: NBA (basketball_nba), EL (basketball_euroleague)
  history.py         резултати и линии: ESPN за НБА (табло + линиите на ESPN BET на всеки мач, кеш на диска), Евролига - официалното API
  odds_api.py        цени (h2h, spreads, totals, регион eu, 3 кредита на първенство); /events е безплатно - първо проверка има ли мач до 36 ч
  market.py          средна / най-добра (с букмейкъра, без борсите) / Pinnacle; честни шансове (степенно махане на маржа); ценови ръб >= 3%
  model.py           рейтинг атака/защита по отбор, предимство на домакина, умора (втори мач до 30 ч); разлика и сбор - нормални
  tips.py            цените -> fixtures; записът (tips, не се мени; денят 07:00-07:00 БГ); уреждане от историята; мерки на живо
  site.py            site_template.html + DATA -> docs/index.html (GitHub Pages от /docs)
  notify.py          ntfy - СОБСТВЕНА тема (NTFY_TOPIC), не тази на футбола; сутрин: мачовете, цена над честната, вчера
tools/gh.py          create / secret NAME / push / pull / run / status - ключът само от .env, никога не се печата
research/model_backtest.py   моделът назад по протокол (избор 2022/23-2023/24, чиста 2024/25 нататък)
.github/workflows/robot.yml  на всеки час (:41): python run.py cloud, после robot.db и docs/ се комитват
```

## Правила (същите като във футбола)

- Никакви ключове в кода, чата и логовете. `.env` е в `.gitignore`; в облака - тайните ODDS_API_KEY и NTFY_TOPIC.
- Никакви мълчаливи грешки - всяка стъпка лога целия стек и цикълът продължава.
- Всяка промяна на модела - с Brier на walk-forward проверката по протокол, записан ПРЕДИ пускането в docstring-а на скрипта.
- Ако моделът бие пазара - първо се търси грешка (изтичане на бъдеща информация).
- Без размер на залога, без „сигурен залог“; до процент на малка извадка - грешката; парите само като мярка.
- Честен запис: само `tips`, записани преди мача. Историята (`games`) е отделно.
- Кредитите на odds API са ОБЩИ с футбола: таван за баскетбола и резерв, под който не се харчи нищо.
- При тестове локално - временна база (HOOPS_DB, HOOPS_SITE) и подменен notify.send.

## Данни

- НБА: ESPN `site.api.espn.com/.../nba/scoreboard?dates=YYYYMMDD` (само редовен сезон, плейин, плейофи) и
  `sports.core.api.espn.com/.../events/{id}/competitions/{id}/odds` (ESPN BET: коефициенти за победа, хендикап, общо точки - затварящи).
- Евролига: `api-live.euroleague.net/v2/competitions/E/seasons/E{година}/games` - резултати и час (UTC); линии назад няма.
- odds API: NBA, Euroleague, NBL, WNBA (14.10.2026); цени - регион eu (с Pinnacle).
